Academic & System Architecture

This project is an end-to-end Demonstration Prototype. Below is a layout of the technical architecture linking the FastAPI backend (Render) and the Vanilla static frontend (Vercel):

[User Interface (Vercel)]
       |
       | HTTP POST /predict (JSON)
       v
[FastAPI REST API (Render)]
       |
       |-- Load preprocessing.pkl (OneHotEncoder, StandardScaler)
       |-- Load best_model.pkl (Decision Tree Classifier)
       v
[Machine Learning Inference]
       |
       |-- Compute Probability P(Risk)
       |-- Run Counterfactual Baselines P(Risk \ Feature)
       v
[JSON Response Payload]
       |
       | (Probability, Category, Local Factor Attributions)
       v
[Charts & Explanations Rendered]

Software Stack

  • Frontend: HTML5, CSS3 (Teal Medical Glassmorphism Design System), JavaScript (ES6+), Chart.js.
  • Backend API: Python 3.11, FastAPI, Uvicorn, Pydantic, Scikit-learn, Joblib.
  • Infrastructure: Render (API Backend Service), Vercel (Static Dashboard Hosting).

⚠️ CRITICAL MEDICAL WARNING & CLINICAL LIMITS

This application is an **academic machine-learning prototype** developed for demo and risk-factor awareness exercises. **It is NOT a medical device, is not FDA-approved or CE-certified, and CANNOT confirm or rule out oral cancer.**

Model predictions depend on the underlying tabular academic training dataset and are not clinically validated or representative of real-world patient diagnoses. This platform **must never** be used as a substitute for professional clinical screening, biopsy, diagnosis, or consultation with a dentist, oral pathologist, or ENT physician.

If you are experiencing persistent oral sores, bleeding, difficulty swallowing, red or white patches, or swelling, please consult a qualified healthcare provider immediately.

🔒 Data Privacy & Security

We respect patient confidentiality and clinical privacy standards:

  • No Personally Identifiable Information (PII) (names, emails, ID numbers) is ever requested, captured, or transmitted.
  • All user inputs are processed dynamically in memory on the server during the API request and are never written to disk, databases, or logs.
  • Calculations inside the browser dashboard are refreshed and forgotten upon reloading the page.
